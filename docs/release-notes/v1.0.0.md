SizeTrail is a permanently read-only macOS storage attribution explainer for developer toolchains. It never deletes, moves, or modifies anything; its only output is stdout and stderr.

## Why this release exists

Earlier previews could name Xcode and Homebrew stores, but Docker Desktop still sat outside the report. Its host disk image and daemon object sets are different measurement planes: adding them, or subtracting one from the other, would invent a remainder the public APIs do not give. The JSON schema was also still marked unstable, so a later reader could not tell a preview document from a frozen one.

## What changed

The scan document schema version 1.0.0 is frozen. `explain --from` rejects a v0.x report instead of reading it as best effort. The locked schema, measurement-basis catalog, and empty-scan coverage baseline are generated files in the repository.

SizeTrail now attributes Docker Desktop when the bundled CLI and the per-user Unix socket are present. The host VM disk image is measured as a filesystem path. Images, containers, volumes, and build cache are separate object-set findings with vendor counts and rounded sizes. Those four categories are never summed, and they are never subtracted from the host allocated footprint. A successful daemon inventory always records that an inactive store can remain on the same disk image.

`--no-docker` is an explicit user exclusion and succeeds. Exact `--exclude` covers the default disk-image root and a custom DataFolder discovered from Docker Desktop settings. Object-set findings do not accept a path exclude.

A Homebrew cask whose artifact has moved outside the prefix is a declared scope boundary. It no longer makes the Homebrew region unmeasurable.

The CLI, doctor, live explain, deny-write sandbox, and compiled rule set include all three adapters: Homebrew, Xcode, and Docker.

## Known coverage boundary

Hosted CI does not install Docker Desktop. A runner without it reports `not_present` and must not be read as a live Desktop proof. Docker advice prints vendor commands and never runs them. `system prune --volumes` is documented as deleting stopped containers and unused objects; it is not presented as a one-click next step.

This release does not reconcile Apple's System Data figure or promise a reclaim amount. Reports use allocated-footprint intervals and structured uncertainty.

## Verifying what you downloaded

Check the archive against the published checksum file, run `sizetrail --version`, and confirm the architecture with `file sizetrail`. Each archive contains only the `sizetrail` binary.
