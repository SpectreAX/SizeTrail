SizeTrail is a permanently read-only macOS storage attribution explainer for developer toolchains. It never deletes, moves, or modifies anything; its only output is stdout and stderr.

## Why this release exists

Earlier builds could not say which build they were. There was no `--version`, `--help` did not carry one, and the scan document's `tool_versions` map holds the versions of *external* tools, not of SizeTrail. The only version-shaped field was `schema_version`, which describes the JSON schema and deliberately did not change in v0.1.1 even though the binary did.

That gap made the upgrade notice on v0.1.0 only half usable: it asked holders of that build to move to v0.1.1 without giving them a way to check which one they had, short of downloading again and comparing checksums. Bug reports had the same problem.

This release adds `--version`, and puts `tool_version` at the top level of the `scan` and `doctor` documents, as a peer of `schema_version` rather than inside `environment`. The build version is not host-dependent, so it must not be substituted by the injected values a fixture uses, and the two versions advance on different schedules. Placing them side by side makes that difference visible instead of inviting the confusion described above.

## Upgrading

If you are on v0.1.0, read its release notes: that build can omit an entire store category from its report when a stray file sits beside the directories a rule enumerates. v0.1.1 fixed it. This release adds no attribution changes on top of v0.1.1.

## Scope and limits

This is a technical preview. The JSON schema is explicitly unstable, and `schema_version` still reports the same unstable schema as earlier previews. Attribution covers one toolchain, Xcode and CoreSimulator. It does not reconcile Apple's System Data figure, and it reports intervals rather than a single reclaim number, because shared blocks and snapshots make an exact figure unavailable through public APIs.

Known uncovered boundaries are stated rather than papered over: writes performed by an unsandboxed daemon on our behalf, writable file descriptors inherited before the sandbox applies, dependency code paths never executed, and `iOS DeviceSupport` attribution, which cannot be exercised on a hosted runner because it requires a physically connected device.

## Verifying what you downloaded

Check the archive against the checksum file published alongside it, then confirm the architecture with `file sizetrail`. Each archive contains only the `sizetrail` binary, and it can now report its own version.
