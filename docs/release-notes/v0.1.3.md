SizeTrail is a permanently read-only macOS storage attribution explainer for developer toolchains. It never deletes, moves, or modifies anything; its only output is stdout and stderr.

## Why this release exists

Earlier previews treated a symbolic link or another non-regular entry inside a measured store as a fatal traversal error. One normal link could therefore make the whole store unmeasurable. This is common in framework build products, where versioned library and bundle layouts use symbolic links.

## What changed

Store traversal now enumerates symbolic links and other non-directory entries without following them. Each entry contributes only its own logical and allocated footprint. A link target already present in the store is not counted again through the link.

The checked-in Xcode fixture now contains a link inside DerivedData. Its regression test verifies both that the store remains measurable and that the reported values equal the regular artifact plus the link itself. The same test was run against the previous error branch and failed, so it guards the behavior in both directions.

## Scope and limits

This is a focused correction to the released Xcode adapter. It does not add another toolchain, change the unstable JSON schema, follow links, or broaden SizeTrail's read-only boundary. Homebrew attribution remains scheduled for v0.2.0 and is not part of this release.

## Verifying what you downloaded

Check the archive against the checksum file published alongside it, then run `sizetrail --version` and confirm the architecture with `file sizetrail`. Each archive contains only the `sizetrail` binary.
