SizeTrail is a permanently read-only macOS storage attribution explainer for developer toolchains. It never deletes, moves, or modifies anything; its only output is stdout and stderr.

## Why this release exists

Homebrew spreads developer storage across the user cache and log directories, its installation prefix, its repository, Cellar, Caskroom, and taps. Treating that layout as one directory would either miss known storage or cross ownership boundaries. Running `brew` to ask about it would also violate SizeTrail's contract: commands that look observational can update metadata, caches, or analytics state.

## What changed

SizeTrail now attributes Homebrew caches, logs, installed kegs, casks, and taps without executing `brew`. It reads version evidence from the repository's Git metadata. Missing version evidence degrades the report but does not discard measurable stores.

The user HOME and Homebrew prefix are independent measurement roots and remain separate findings. SizeTrail never adds their totals together. Symbolic links are measured only for their own footprint and are never followed.

Cask artifacts moved outside the prefix produce a typed coverage gap. In particular, `/Applications` is not measured as part of Homebrew: a staged link is evidence that attribution left the prefix, not permission to count its target.

Homebrew cache findings render Homebrew's cleanup command with automatic dependency removal disabled as advice only. SizeTrail never runs it, and the report explains that Homebrew's dry-run form is not a complete preview. Installed Cellar content and logs receive reveal-only advice.

The CLI now supports Homebrew in `scan`, `doctor`, live `explain`, and exact `--exclude` validation. `--no-homebrew` records an explicit user exclusion. Built-in Homebrew rules remain compiled into the binary; there is no external rule or configuration directory.

## Known coverage boundary

This release does not parse `brew.env`, so a Homebrew cache or log path redirected there is not discovered. Missing default cache paths produce an `absent_or_changed` coverage gap rather than a claim of completeness.

This remains a technical preview. The JSON schema is explicitly unstable. The report uses allocated-footprint intervals and structured uncertainty; it does not reconcile Apple's System Data figure or promise a reclaim amount.

## Verifying what you downloaded

Check the archive against the published checksum file, run `sizetrail --version`, and confirm the architecture with `file sizetrail`. Each archive contains only the `sizetrail` binary.
