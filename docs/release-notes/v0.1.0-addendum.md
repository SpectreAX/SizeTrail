## Known defect in this release — please use v0.1.1

This release can silently omit an entire store category from its report.

When a non-directory entry sits beside the directories a wildcard rule path enumerates, the whole expansion aborts. A `.DS_Store` inside `DerivedData`, `Archives`, or `iOS DeviceSupport` is enough, and those are directories people open in Finder. The affected category is then replaced by a `traversal_failed` coverage gap.

The failure is honest rather than wrong. The gap is typed, the region is reported as unmeasurable, and the exit code signals an incomplete scan, so this release never printed an incorrect number. But it can leave a whole category out of the report without that being obvious at a glance, which defeats the purpose of an attribution tool.

v0.1.1 fixes it. A wildcard component now skips entries that are not directories, since they are not stores.

This note was added after publication rather than leaving the finding in the commit history, because a new tag does not tell anyone already holding this binary that it under-reports.
