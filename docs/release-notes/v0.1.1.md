SizeTrail is a permanently read-only macOS storage attribution explainer for developer toolchains. It never deletes, moves, or modifies anything; its only output is stdout and stderr.

## Why this release exists

v0.1.0 could drop an entire store category from its report. When a non-directory entry sat beside the store directories a wildcard rule path enumerates — a `.DS_Store` inside `DerivedData`, `Archives`, or `iOS DeviceSupport` is enough — the whole expansion aborted and that category was replaced by a `traversal_failed` coverage gap.

The failure was honest rather than wrong: the gap was typed, the region was reported as unmeasurable, and the exit code signalled an incomplete scan. No incorrect number was ever printed. But a tool whose entire value is attribution should not silently omit whole categories, so this release fixes it.

A wildcard component now skips entries that are not directories, because they are not stores. A rule path that literally names a non-directory still reports a gap, since that is a rule defect worth surfacing.

## Also in this release

Simulator device sets are now measured even when the exact CoreSimulator version gate does not match. Those bytes live in plain directories and need no version-gated probe; only the device name and runtime association do. When the gate misses, the device sets are measured and a `simulator_identity_unavailable` gap declares that their identity is unknown. Nothing is fabricated from directory names.

A non-blocking CI lane now runs a real scan against a hosted runner's real Xcode installation, its prebuilt simulator device sets, and freshly built `DerivedData`. Both defects above were found by that lane on its first run, against directory shapes no fixture in this repository contained.

Published benchmark assets now carry the runner image identity. The timing describes that image and that fixture only, and must not be read as a performance claim about any other machine, nor charted across image rotations.

These release notes are a file in the repository and are checked by the same claim and quantitative-documentation gates as the rest of the public copy.

## Scope and limits

This is a technical preview. The JSON schema is explicitly unstable. Attribution covers one toolchain, Xcode and CoreSimulator. It does not reconcile Apple's System Data figure, and it reports intervals rather than a single reclaim number because shared blocks and snapshots make an exact figure unavailable through public APIs.

Known uncovered boundaries are stated rather than papered over: writes performed by an unsandboxed daemon on our behalf, writable file descriptors inherited before the sandbox applies, dependency code paths never executed, and `iOS DeviceSupport` attribution, which cannot be exercised on a hosted runner because it requires a physically connected device.

## Verifying what you downloaded

Check the archive against the checksum file published alongside it, then confirm the architecture with `file sizetrail`. Each archive contains only the `sizetrail` binary.
